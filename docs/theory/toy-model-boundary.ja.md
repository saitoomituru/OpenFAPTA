## 1. Shannon境界

対象世界を`X`、観測を`Y`、決定的加工を`T(Y)`とすると、Markov連鎖`X -> Y -> T(Y)`では
データ処理不等式により次が成り立つ。

```text
I(X; T(Y)) <= I(X; Y)
```

既存資料の要約、圧縮、分類は利用可能性を高められるが、外界についての新しい観測そのものではない。
新しい外界情報には、測定、実験、接触、または別の情報源が必要になる。

これは経済価値が情報量だけで決まるという主張ではない。価値、意味、使いやすさ、計算量をShannon情報量と
同一化しない。

## 2. FIAT／MMT境界

MMTやChartalismには、税債務が国家通貨への需要を作り、通貨発行者が名目的な支出を先行できるという説明がある。
OpenFAPTAはそれを「令呪」というFAPTA比喩へ接続するが、同一理論として再定義しない。

トイモデルが扱うのは次の差である。

```text
予算・通貨・契約による動員可能性 != 現場の実行能力
会計に記録された出力             != 全ての物理作用
将来benefitへの信念               != benefitの物理実現
将来benefitへの信念               = 資源配分を変え得る入力
```

最後の行はモデル内の因果入力として実装する。現実経済での効果量、方向、持続期間は別の実証課題である。

## 3. risk／benefitの対称保存

既存の安全ゲート`unknown != pass`だけでは、未知benefitが危険側の都合で消される可能性がある。
OpenFAPTAは二本の不変条件を同時に使う。

```text
unknown risk    != safe
unknown benefit != zero
```

トイ判定器は、物理的強制停止を`BLOCK`、探索費用が損失上限を超える場合を`RESOURCE-WAIT`、
未知benefitへの明示的信念と損失上限がある場合を`SANDBOX`へ送る。これは投資助言でも安全保証でもない。

## 4. 反例としての探索モデル

既知の報酬だけを選ぶ方針と、未知枝を一度観測してから選ぶ方針を比較する。fixtureには高benefit枝を一つ含める。
探索方針が勝つ結果は「探索は常に得」という証明ではない。「未知を常にゼロと置く方針では到達できない
benefitが存在する世界」を示す反例である。

今後は高損失枝、観測費用、誤観測、信念更新、複数主体、退出不能性を追加し、探索礼賛モデルにも反例を入れる。

## 5. 期待分布と観測結果

観測前の期待、主観確率、シナリオ、関連周辺benefitは、実現結果ではない。金融工学では将来期待が現在の
価格、信用、投資、資源配分を動かす入力になり得るため、それを「信仰だから存在しない」と除外すると
モデルの入力を失う。一方、情報子工学では期待をSource、探索実践をAgency action、観測結果をEffectとして
分け、期待を結果OAEへ昇格しない。

```text
belief / expectation -> allocation effect
mining action        -> observation channel
observed result      -> evidence
```

この三段を波動関数の収束やSchrödingerの猫へ類推してよいが、OpenFAPTAが主張できるのは
「観測前候補と観測後結果を別状態にする情報子工学的アプローチ」までである。量子力学的重ね合わせ、
量子測定、物理的波動関数を実装または立証したとは表示しない。

信仰が終了したときは`LAST_ORDER`へ遷移する。Last Orderは観測されなかったbenefitをゼロへ更新せず、
現在の探索配分を止める。これにより、期待を無限継続する事故と、途中終了を不存在証明にする事故を同時に避ける。

## 6. 起動動機と工学事実

この初期実験では、利用者の信仰が探索依頼を発動し、Codexがcodeへ写像し、Python interpreterとtest runnerが
fixtureを実行した。次は別の主張である。

1. 利用者がbenefitを信じて探索を依頼した: 発話と対話履歴に基づくInitiator／beliefの事実
2. codeが指定入力を演算し、11試験を通過した: receiptで追跡できるLayer A工学事実
3. 未知benefitを保持する設計が現実経済を改善する: 未検証仮説

入力動機が信仰であることは2を信仰へ変換しない。2が成立したことも3を自動証明しない。
証拠資格は動機の社会的分類ではなく、対象scope、protocol、実行、観測、receiptで判定する。
