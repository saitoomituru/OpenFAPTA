## 1. 何を作るか

OpenFAPTAは、回収可能性と未知コモンズの探索余地を発見・登録・試行・再評価し、M次元のポートフォリオとして信用創造を支える、オープンで汎用的なマーチャントエンジンである。FAPTAはFold Autonomous Potential Transaction Architectureの略。

主な利用者は通貨発行母体、信用供与主体、共同体、事業・研究の資源配分者。クレジットカードのマーチャントシステムは業務上の類似例であり、本設計では与信根拠となる回収可能性と探索余地へ責務を置く。特定のカードネットワーク仕様を実装したという意味ではない。

未来の価格や成功を当てることより、どの未来を試せるか、回収経路はあるか、未知を埋める探索範囲は残るかを管理する。回収は現金返済だけへ固定せず、各Foldが何の回収・再利用・供給能力を扱うかを宣言する。

## 2. 探索とリトライ

1. 回収候補、未知、探索フロンティアを発見して登録する。
2. 対象、条件、投入資源、観測方法、停止・再開条件を定めて試す。
3. 結果、失敗、未到達、新しく見つかった未知を記録する。
4. 条件・接続先・方法を変えたリトライの余地を評価する。
5. 回収可能性と探索余地を更新し、次のポートフォリオへ返す。

一回の失敗、未観測、探索経路の終了、探索範囲の枯渇を分ける。`LAST_ORDER`は現在の経路を閉じるもので、別主体・別条件での回収可能性を不存在へしない。既存データの再加工と新たな試行・観測も区別する。

## 3. M次元チャートと面積

チャートには、回収候補、探索可能範囲、ラリティ、ボラティリティ、時期、資源依存、再試行能力などを、採用した定規のもとで載せる。固定の次元数や唯一の総合価値点へ潰さない。

「面積」は、その構成で宣言する測度による評価量を指す。Foldの接続・分離・階層というトポロジー、評価軸、測度、単位、集約則、比較可能な範囲を別々に明示する。トポロジーの指定だけで面積値や通貨額が自動的に決まるとはしない。異なる測度の値は、変換条件を定義するまで無断で足し合わせない。

| チャートの形 | 読むこと |
| --- | --- |
| 極端に大きいボラと広いフロンティア | 回収は未確定でも試せる範囲は広い。観測路と再試行条件を調べる |
| 小さいボラ、安定、薄い髭 | 安定した回収と、新たな探索余地の薄さを別軸で保持する |
| 他Foldの資源を使って伸びた髭 | 増加の出所、相手側の消耗・回復・回収条件まで追う |
| 未計測・非有界として語られるボラ | 使用した定義と未確定を保持する。Hi-Zへ数値の無限大を代入しない |

未知コモンズが枯れていないこと、探索フロンティアが残ること、その組合せから回収能力が増えることを、信用創造の根拠として評価する。探索範囲の拡大とボラの変化はプラスサム候補の観測軸であり、同時に他Foldへの資源移転・消耗・同じ資源の重複計上を追う。評価scopeを変えて他Foldの損失を隠した増加は、全体の増加と区別する。

## 4. 構成アルゴリズムの競争

利用者は政治思想、通貨発行思想、共同体の目的に応じて、どのFoldを採用し、どう接続し、どの面積・回収・探索方針で信用を組むかを選ぶ。個人・組織・共同体・発行母体で同じ構成原理を再帰的に使うことを、ここでのフラクタル性とする。各階層の権限や資源を同一化するものではない。

競争対象は、コモンズを維持し、未知を掘り、回収可能性と探索範囲を育てる構成アルゴリズムである。OpenFAPTAは特定思想を唯一の既定値へ固定しない。同じ入力と資源条件で、採用Fold、測度・単位、policy revision、観測・再試行履歴、消費した資源と残った未知を比較可能にする設計を目指す。

## 5. 通貨・交換単位・帳簿との接続

交換単位、通貨の発行・残高、決済、分散台帳の合意方式は外部実装の責務とする。暗号通貨、ステーブルコイン、プレミアム付き商品券、ポイント、その他のFIAT v2構想など、採用者が選ぶ実装へ接続する。ここで列挙することは、それらのadapterが既に存在するという表示ではない。

評価上の面積単位と、外部で交換に使う単位は別である。OpenFAPTAは株式・信用取引・通貨発行等を支える与信根拠の管理側に位置する。「過去方向の与信／未来方向の回収可能性」は本研究の比較軸であり、既存FIATの全てが過去しか評価しないという普遍命題にはしない。

## 6. 現在動くものと実装課題

| 責務 | 現在の状態 |
| --- | --- |
| 資源の存在・利用許可・維持者・変換路・時期 | `ResourceCandidate` / `activation` toy |
| 台帳の可視性と物理作用の区別 | `ActionEvent` / `ledger` toy。台帳製品の実装ではない |
| 未知benefitの保持と探索経路 | `ExplorationCandidate` / `route_exploration` toy |
| 期待・試行・観測・Last Orderの区別 | `ExplorationProcess` / `exploration` toy |
| 発見・登録・リトライ履歴の永続管理 | 設計・実装課題 |
| 汎用M次元チャート・面積測度・フラクタル構成 | 設計・実装課題 |
| コモンズ枯渇・他Fold資源・プラスサム候補の検出 | 比較実験の設計課題 |
| 通貨・帳簿・決済adapter | 外部責務。現行repoにadapter実装なし |

既存CLIの`ledger`という名前を分散台帳engineの能力表示へ昇格しない。現在のtoyを入口として、設計の検証を進める。

## 7. 次に比較するfixture

- 広い未知領域、高い／未推定のボラ、限られた試行資源がある場合。
- 安定回収を維持できるが、新しいフロンティアがほぼ増えない場合。
- 一方のFoldの増加が他Foldの消耗に由来する場合。
- 同じコモンズ資源を別Foldで二重に数えてしまう場合。
- 初回失敗後、方法や観測路を変えることで回収候補が見つかる場合。
- 観測設備を失い、対象資源は残るが探索範囲へ到達できなくなる場合。
- 同じ測度での単位変更と、測度自体の変更を分けて比較する場合。

単一の勝者や万能scoreを先に作らず、どの構成が何を発見し、消費し、保持し、停止・再開できたかを比較する。既存の[Issue #8](https://github.com/saitoomituru/OpenFAPTA/issues/8)（未来信用・配分比較）、[#3](https://github.com/saitoomituru/OpenFAPTA/issues/3)（探索能力）、[#4](https://github.com/saitoomituru/OpenFAPTA/issues/4)（利用Context）で継続する。
